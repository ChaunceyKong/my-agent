## Security, recovery and evidence limits

- Main still owns filesystem/database/secrets/model/update operations; Renderer has no Node require, generic IPC, arbitrary log/feed/path editing or returned credentials. No product test hook, authorization bypass or new feature is introduced in final acceptance.
- Friendly Renderer recovery reloads only the UI, not effects/tasks. Browser offline state remains a connectivity hint, not Provider/Ollama health. Fatal Main failures exit rather than guessing how to replay. Logs contain only bounded fixed-code/context records; export rebuilds their strict schema.
- Installation is explicit and admission is Main-owned. In-flight reservations and global durable/recovery barriers reject installation. Only proven pre-handoff failure/cancellation can reopen admission; confirmed/uncertain installer handoff, late errors or prevented quit do not prove rollback and keep the gate closed. Fake adapters establish these local contracts, not OS installation success.
- Current builds are update-disabled: development/unconfigured/portable actions return fixed states without calling real update actions. Package HTTP evidence is limited to Electron session observation after first-window readiness, not an OS/Node/whole-startup capture. No real Provider or updater check/download/install is exercised.
- Native workspace/export dialogs use Main-side test substitutions where automated; manual Windows chooser interaction, cancellation and focus are not verified. Tests do not install, uninstall, publish, create certificates or run unsigned real update delivery.
