# v0.5 Task 5 — Windows package verification

Date: 2026-10-03. Implementation baseline: `31c1acf`, current branch `main`.
This report covers release configuration and local Windows packaging only. Task 6 final acceptance has not started; the entire v0.5 release is not declared complete.

## Configuration and preservation

- Product, package-lock root/package versions and the existing cockpit display are `0.5.0`. `shared/app-version.ts` supplies the display value; a unit test asserts alignment with package/lock metadata.
- `npm run build:win` explicitly builds x64 NSIS and portable; `build:mac` specifies DMG/ZIP; `build:linux` specifies AppImage. Each packaging script invokes electron-builder with `--publish never` and a platform/version-specific output directory. No trusted update feed, signing identity or publication credentials were invented.
- `scripts/package-desktop.mjs` refuses an existing output directory before invoking the builder. `release/win-v0.5.0` was confirmed absent before this first build. A later direct wrapper invocation returned the expected refusal rather than overwriting the new artifacts. To rebuild, use a separately approved new output; the wrapper does not delete or clean existing releases.
- Only the new `release/win-v0.5.0` was written. Root's read-only before/after hash comparison found the existing `release/win-v0.1.0` unchanged. Original user documents and all four original untracked entries remain unstaged. Generated release binaries are not committed.

## Reproducible packaged smoke

Run `npm run test:package` after a successful Windows build. A separate Playwright config/test directory prevents the normal development Electron suite from depending on release artifacts. Tests use independent `mkdtemp` userData/workspace/runtime-temp directories, normal named production IPC and no product test hooks or consent bypasses.

Final serial result: **2/2 passed, 18.8 seconds**.

1. **Unpacked real executable:** Playwright launches `win-unpacked/Agent Team Desktop.exe`, not the development Electron executable. Main confirms `isPackaged:true`, version `0.5.0`, `getAppPath()` ending in `app.asar` and the exact isolated `--user-data-dir`. The test verifies the Renderer has no Node require or generic filesystem/process/database/credential IPC. All five update actions return `disabled/unconfigured`. A normal project creation persists the workspace and exactly one initial Channel; after close, read-only SQLite inspection confirms schema version 18 and the project, and a fresh packaged launch restores it and the dark theme. This proves creation/read/restart persistence, not a complete update/delete CRUD test.
2. **Actual portable launcher:** Direct Playwright Electron launch initially timed out because the NSIS wrapper did not supply the expected inspector stderr transport. The final test starts the actual portable EXE with structured arguments, `shell:false`, hidden launch and a localhost browser CDP port. CDP's observed browser PID plus a read-only CIM query confirms its executable lies strictly inside this test's self-extracted runtime-temp using `path.relative`, not the win-unpacked path. UI/API verifies version `v0.5.0`, no Renderer Node require, `disabled/portable`, actual isolated SQLite startup schema/read and dark-theme persistence after restart. There is no Main inspector assertion for portable. Its project-write persistence and native chooser are not separately tested. Both launches close normally; the wrapper exits within a 10-second bounded wait, and its runtime-temp directory is empty before test-owned cleanup. Failure to confirm exit retains the test root instead of recursively deleting a live runtime.

Network evidence is deliberately limited: unpacked smoke observed **zero Electron session HTTP(S) requests after the first window was ready** through close. This is not an OS-wide/Node/whole-startup network capture. Both packaged modes return disabled update states; the unchanged fixed unconfigured/portable Main policy and Task 4 unit tests establish no updater check/download/install calls. No real Provider is configured or called during these package tests.

Native directory selection evidence is **Main-dialog substitution only** for unpacked. The test supplies the disposable workspace from a test-side replacement of `dialog.showOpenDialog` and exercises the real opaque selection and project IPC. Manual OS chooser interaction/cancellation/focus has not been verified; portable has no chooser test. No filesystem capability or path-editing bypass was added to Renderer.

Disposable visual evidence: `test-results/package-unpacked-dark.png` and `test-results/package-portable-dark.png`. These are test outputs, not permanent release artifacts.
