# v0.5 long-history measurement

## Reproducible fixture

Windows development Electron, isolated temporary userData and workspace, no external model requests. `tests/e2e/v05-history.spec.ts` inserts 3,000 durable messages into the normal SQLite database, with alternating author roles and 11 repeating content-length classes. It also inserts 900 model-attempt events and 300 completed Runs. All 4,200 logical rows are included in the observation; attempts and Run statuses are not exempted from windowing.

Run `npm run build`, then `npx playwright test tests/e2e/v05-history.spec.ts`. The test logs `HISTORY_MEASUREMENT`, verifies all durable counts through the normal snapshot IPC, and exercises native scrollbar and earliest/latest navigation. SQLite fixture insertion is performed only by the test host; no test-only Renderer or production IPC is added.

## Observed baseline and windowed result

At baseline `ab95f3c`, the log mounted 3,000 message articles, 900 attempt rows and 300 Run statuses: 4,200 rows and 24,000 descendant DOM nodes. The viewport was 497 px tall and its fully laid-out scroll extent was 1,916,120 px. One reload-to-ready observation was 4,459 ms.

After windowing, the same persisted 4,200-row fixture mounted 7 message rows and 62 descendant DOM nodes at the latest position. The viewport was 461 px tall after adding the history-navigation bar. Its estimated scroll extent was 1,374,753 px; visited variable-height rows replace estimates with actual measurements. One scoped reload-to-ready observation was 429 ms.

The two timing observations use different readiness markers: the old attempt-tail marker and the new latest-message marker. They are not a controlled speed ratio. DOM mount counts are the directly comparable resource observation; timings are single development-host observations, not packaged startup or production latency guarantees. Scrollbar extent is an estimate until rows are visited; no message text or durable history is truncated.

The final complete-suite run observed the same 7 mounted rows and 62 DOM nodes, an estimated extent of 1,374,762 px and 682 ms to the latest-message marker. Its first-token visibility observation was 512 ms with 11 mounted rows. These remain loopback/development test observations and do not establish a production latency bound or a speed ratio against the older baseline.

## Implementation and verification boundaries

- All message/preview, attempt and Run rows share a stable timestamp-ordered window with measured heights, six-row overscan and at most 80 mounted rows. Timestamp ties preserve original order. Completed actual-model provenance and attempt-not-success wording are retained.
- While reading history, a stable row ID and pixel offset preserve the reading anchor. New stream output and terminal snapshots do not pull the reader to the bottom. Follow mode applies only within 80 px of the bottom, and viewport-height changes are handled without waiting for polling. Native keyboard scrolling and explicit earliest/latest navigation keep older rows reachable.
- A streaming preview remains separate from a completed durable message. Real Electron tests wait for actual preload delta delivery and Renderer durable-message counts before checking anchors. They exercise first-token visibility with long history, completion without duplicate previews, channel reset, cancellation and a deliberately late stale Main event.
- Already-bound token deltas update previews immediately and schedule at most one snapshot refresh per channel per 40 ms. Fake-timer tests cover a 100-token burst, terminal follow-up during an in-flight read, unknown bindings, cancellation/generation guards, polling and disposal. Main dispatch and consent behavior are unchanged.
- No dependency, database, IPC, version, package or lazy-loading changes are required by this stage.
